# ADR-003 — Локальный инференс: llama.cpp sidecar, Apple Foundation Models на iOS, модели по умолчанию

Статус: принято (2026-09).

## Контекст

Целевое железо: 8 ГБ системной RAM (мало — браузер сам ест 2–4 ГБ) и RTX 4060 с 8 ГБ VRAM.
Бюджеты: суммаризация страницы < 3 с; ИИ-слой в простое < 300 МБ RAM и < 5% CPU. Приоритет
локальных моделей для приватных данных. На iOS память приложения ограничена, но есть системный
LLM Apple (Foundation Models framework) и Core ML/Core AI.

## Варианты

1. **llama.cpp в процессе** (крейт `llama-cpp-2`) — минимальная латентность, но падение драйвера
   CUDA/Vulkan или OOM в VRAM убивает браузер; конфликт за GPU с композитором Chromium.
2. **llama.cpp как sidecar** (`llama-server`, OpenAI-совместимый HTTP на localhost/named pipe) —
   изоляция сбоев, независимый рестарт, несколько моделей с LRU, готовые GBNF-грамматики,
   KV-cache q8_0, `--flash-attn`; накладные расходы HTTP на localhost — < 1 мс.
3. **Ollama как основной** — удобно разработчикам, но ~10% overhead, свой формат, ещё один демон.
4. **ONNX Runtime GenAI / WebGPU** — для LLM уступает llama.cpp по зрелости квантизаций и
   грамматик; WebGPU в WebView на iOS отсутствует.
5. **MLX** — только Apple.

## Решение

- Десктоп: **`llama-server` sidecar**, поставляется с браузером, собран под CUDA и Vulkan (выбор
  по обнаружению GPU; CPU-fallback). Управляется `model-gateway`: запуск по требованию, выгрузка
  по таймауту простоя, LRU при нехватке VRAM, health-check и рестарт. Ollama и любой
  OpenAI-совместимый локальный сервер — как внешние провайдеры (обнаружение, но не зависимость).
- iOS: **Apple Foundation Models** как «быстрая» и «умная» модель по умолчанию (0 байт весов у
  нас, работает офлайн), **Core ML** для EmbeddingGemma и классификаторов; llama.cpp/Metal — опция
  для собственных ≤ 1.7B моделей на устройствах с ≥ 8 ГБ.
- Вспомогательные модели (эмбеддер, классификатор интентов, детектор PII, VAD) — **ONNX Runtime**
  на обеих платформах (CoreML EP на iOS, DirectML/CPU на Windows).
- Модели по умолчанию (все открытые веса):

| Роль | Windows | VRAM | Резидентность |
|---|---|---|---|
| fast | Qwen3-4B Q4_K_M, ctx 8K, KV q8_0 | ~3.5 ГБ | резидентна при активной работе, выгрузка через 10 мин простоя |
| smart | Qwen3-8B Q4_K_M, ctx 8–12K, KV q8_0 | ~6–6.5 ГБ | по требованию; вытесняет fast (LRU) |
| vision | Gemma 4 E4B | ~6 ГБ | по требованию |
| embed | EmbeddingGemma-300M, выход 256-dim (MRL) | ~0.3 ГБ | резидентна (ONNX, может жить на CPU) |
| asr | whisper.cpp small | CPU | по требованию |
| cpu-fallback | Qwen3-4B / Phi-4-mini на CPU | RAM ~2.7 ГБ | только если нет GPU; пользователь предупреждён |

- Пользователь может заменить любую роль любой GGUF/провайдером; пресеты «8 ГБ VRAM», «12 ГБ»,
  «16 ГБ+», «CPU only».
- Составление промптов — единый формат сообщений `model-gateway`; структурированный вывод — через
  JSON-schema → GBNF на llama.cpp и `response_format` у облачных провайдеров.

## Последствия

- Жёсткое правило VRAM: `fast + embed + 1.5 ГБ запас композитору ≤ 8 ГБ`; `smart` и `fast`
  одновременно не держим — планирование агента переключает модель (стоимость переключения 1–2 с
  с NVMe, скрывается стримингом «думаю»).
- Суммаризация укладывается в 3 с только на `fast`; `smart` для суммаризации не используется.
- Sidecar — отдельный процесс, значит нужен явный контроль: только localhost/pipe, случайный
  токен на запуск, никаких сетевых интерфейсов наружу.
- Бенчмарк-гейт в CI (`bench/inference`): p95 суммаризации 3K токенов на референсной машине.
