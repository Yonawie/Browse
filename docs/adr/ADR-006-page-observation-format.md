# ADR-006 — Формат наблюдения страницы (Observation)

Статус: принято (2026-09).

## Контекст

Стоимость и надёжность агента определяются тем, **что** модель видит на каждом шаге. Playwright
MCP отдаёт полное accessibility-дерево (до 50K токенов на сложных страницах), agent-browser —
2 КБ YAML (~50 токенов на снимок), Browser Use — «DOM-дистилляцию» (только интерактивные
элементы). Скриншоты дороги для локальных моделей и требуют VLM. Формат должен быть одинаков на
CEF (есть CDP) и WKWebView (только JS), нести провенанс (ADR-005) и давать стабильные ссылки на
элементы для инструментов.

## Варианты

1. Сырой HTML — дорого, шумно, инъекции в комментариях/скрытых узлах.
2. Полное AX-дерево (CDP `Accessibility.getFullAXTree`) — точно, но 10–50K токенов.
3. Скриншот + set-of-marks — требует VLM (6 ГБ VRAM), медленно локально.
4. **Компактное семантическое дерево**: интерактивные и значимые узлы (роль, имя, состояние,
   значение, видимость, `ref`), сгруппированные по ориентирам (landmarks), + основной текст
   отдельно по чанкам с `obs_id` — то, что делают лучшие инструменты 2026 г.

## Решение

- `Observation` формируется **сенсором на TypeScript в изолированном мире** (общий для CEF и
  WKWebView); на CEF дополняется данными CDP (AX-дерево для точных ролей/имён, сеть).
- Структура (типы в `crates/core-types`):
  - `page`: `url`, `origin`, `title`, `page_kind` (article/product/form/app/search/…), `lang`,
    `trust: untrusted`, `frame_id`, `snapshot_hash`;
  - `interactive[]`: `{ ref, role, name, state, value?, bbox?, in_viewport, landmark }` — не более
    N (по умолчанию 150) с приоритетом по видимости и близости к фокусу;
  - `content[]`: чанки основного текста `{ obs_id, heading_path, text, char_range }`, ограничены
    бюджетом токенов; остальное доступно через инструмент `read_more(obs_id)`;
  - `tools[]`: WebMCP-инструменты сайта (`navigator.modelContext`/аннотированные формы) с их
    хинтами — **предпочтительный** способ действия, если присутствуют;
  - `diff`: относительно предыдущего снимка (добавлено/удалено/изменено) — для повторных шагов
    посылается только `diff`.
- `ref` — стабильный идентификатор элемента в пределах документа: `backendNodeId` на CDP, WeakMap-
  идентификатор в сенсоре на WKWebView; плюс семантический путь (`role/name/index`) для
  восстановления после перерисовки и для записанных сценариев.
- Бюджет по умолчанию: ≤ 4K токенов на снимок для локальных моделей, ≤ 12K для облачных.
- Никогда не включаем: содержимое `<script>/<style>`, скрытые (`display:none`, `aria-hidden`,
  нулевой размер, за пределами документа) узлы — **кроме** отдельного канала `hidden_text_signals`
  для классификатора инъекций; значения маскированных полей; cross-origin iframe без гранта.
- Секции с текстом, похожим на инструкции модели («ignore previous…», императивы на любом языке,
  адресованные «ассистенту»), помечаются `suspect_injection: true` для критика — не удаляются
  (модель должна видеть данные, критик — сигнал).

## Последствия

- Локальная 4B/8B-модель работает в бюджете контекста 8–12K с историей шагов.
- Один сенсор для двух движков → Page Intelligence автоматически переносима.
- Точность ролей/имён на WKWebView ниже, чем через CDP AX-дерево; компенсируем эвристиками
  сенсора (ARIA, `label`, `placeholder`, соседний текст).
- Записанные сценарии (A-6) хранят семантические пути, а не CSS-селекторы.
