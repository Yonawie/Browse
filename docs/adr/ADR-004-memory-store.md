# ADR-004 — Хранилище памяти: одна SQLite-БД с sqlite-vec и FTS5

Статус: принято (2026-09).

## Контекст

Память браузера — это история, страницы, чанки, эмбеддинги, граф сущностей, задачи, сессии
агента, журнал действий, гранты политик. Требования: локально, одна файловая единица для
резервного копирования и удаления, каскадное удаление (страница → чанки → векторы → рёбра),
транзакционность между «обычной» историей и векторами, работа на iOS, гибридный поиск
(лексический + семантический) с фильтрами по времени/домену/задаче. Ожидаемый объём одного
пользователя: 20–200K чанков за год.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| SQLite + sqlite-vec (vec0) + FTS5 | Один файл, транзакции, каскады, SQL-фильтры, < 1 МБ расширение, iOS ок, int8/binary квантование | Только точный KNN (ANN не выпущен, issue #25); pre-1.0 |
| LanceDB | ANN, версионирование (time-travel), больше-чем-RAM, BM25 | Отдельный каталог файлов и транзакционная модель, pre-1.0, тяжелее на iOS |
| Qdrant embedded / Chroma | Полноценный ANN | Отдельные сервисы/модели хранения; оверкилл для одного пользователя |
| Своё in-memory HNSW (usearch/hnsw_rs) + SQLite | Быстро | Две системы, ручная синхронизация и восстановление |

## Решение

- **Одна SQLite-БД** (`memory.db`, WAL, `foreign_keys=ON`) — схема в `schema/memory.sql`.
- Векторы — таблица `vec0` (`sqlite-vec`) с partition key по месяцу и вспомогательными колонками
  `domain`, `task_id` для предфильтрации; 256-dim (MRL-усечение EmbeddingGemma), f32 сейчас, int8
  при превышении 200K чанков.
- Лексический индекс — FTS5 (`unicode61`, `remove_diacritics 2`) по тексту чанков; гибрид — RRF по
  результатам двух поисков.
- Абстракция `VectorIndex` в crate `memory`; вторая реализация (LanceDB) — при превышении
  порога 500K чанков или p95 поиска > 100 мс на референсной машине.
- Каскадное удаление через внешние ключи для реляционных таблиц; для `vec0` (виртуальная таблица
  без FK) — триггеры `AFTER DELETE ON chunks`.
- Ретенция: TTL по политике пользователя (по умолчанию бессрочно), «никогда не запоминать» по
  доменам, приватные окна не индексируются.

## Последствия

- Простота бэкапа/экспорта/удаления: один файл. Инспектор памяти — обычные SQL-запросы.
- Ограничение brute-force: 200K × 256-dim f32 ≈ 200 МБ скан ≈ 20–40 мс на CPU — в бюджете;
  партиции сокращают в разы.
- Версионирования «как у LanceDB» нет → аудит памяти делаем сами: таблицы `memories` и
  `page_versions` append-only с `superseded_by`.
