# ADR-001 — Движок рендеринга: CEF на десктопе, WKWebView на iOS, единый EngineAdapter

Статус: принято (2026-09). Владелец: архитектура ядра.

## Контекст

- Целевые платформы: Windows (первая), iOS (вторая). Аудитория — разработчики.
- На iOS Apple глобально требует WebKit; альтернативные движки — только в ЕС через
  BrowserEngineKit с отдельным бинарём и потерей существующих пользователей; за 2.5 года ни один
  вендор не выпустил ничего на этой базе. iOS = WKWebView без вариантов.
- ИИ-агенту нужен низкоуровневый доступ: DOM/accessibility-дерево, сеть, ввод, события навигации,
  изоляция профилей (для агентной песочницы). На Chromium всё это даёт CDP; на WKWebView — только
  инжектируемый JS + `WKScriptMessageHandler` + `WKContentRuleList` + `WKURLSchemeHandler`.
- Маленькая команда: полная сборка Chromium (100+ ГБ, 2–8 ч) и rebase на каждый milestone
  (у Vivaldi 2+ недели на мажорную версию) не по силам без потери скорости разработки продукта.
- Ограничения: open source, нулевая телеметрия.

## Варианты

1. Форк Chromium — максимальный контроль и готовый UI браузера; неприемлемая стоимость поддержки.
2. CEF (Chrome bootstrap) — Chromium как библиотека с готовыми бинарями на каждый milestone,
   полный CDP (`CefBrowserHost::SendDevToolsMessage`), перехват запросов, свои схемы, off-screen
   rendering, поддержка расширений в Chrome runtime; UI браузера пишем сами.
3. Electron — быстро, но Node в браузерном процессе (лишняя привилегированная поверхность рядом с
   агентом), слабые расширения, память.
4. Tauri 2 + WebView2 — минимальный бинарь, CDP есть, но движок закрытый и обновляется/ограничивается
   Microsoft; расширения ограничены; на других десктоп-ОС нет CDP.
5. Qt WebEngine — Chromium 134 в Qt 6.10 против актуальных ~150; регрессии стабильности.
6. Servo — Rust, но v0.4, ежемесячные breaking changes, web-compat не готова; Verso заархивирован.
7. Обёртка над Playwright/CDP — не продукт для пользователя.

## Решение

- Десктоп: **CEF (Chrome bootstrap runtime)** через Rust-биндинги (`cef-rs`/автогенерация по
  C API). Один процесс браузера на Rust, стандартная многопроцессная модель Chromium.
- iOS: **WKWebView**, Shell на SwiftUI.
- Ядро зависит только от трейта `EngineAdapter` (crate `engine-adapter`), реализации:
  - `cef` — production десктоп;
  - `wkwebview` — production iOS (реализация в Swift, мост через UniFFI callback-интерфейс);
  - `cdp-remote` — подключение к любому Chromium по WebSocket CDP: headless-песочница агента,
    e2e-тесты ядра без сборки CEF, отладка;
  - `webview2` — резервный десктоп-бэкенд (Tauri/wry), если CEF-биндинги окажутся блокером.
- Никаких патчей в Chromium в первой фазе; всё, что нужно агенту, берём из CDP + инжектируемого
  сенсора. Если возникнет потребность в патче — это отдельный ADR (CEF допускает патчи).

## Последствия

Плюсы:
- Итерации — секунды (пересборка нашего кода), обновление движка — смена версии бинаря CEF
  (~ежемесячно, LTS-ветки CEF в перспективе).
- Один и тот же CDP-семантический слой на десктопе и в песочнице; iOS вынуждает держать
  сенсор на чистом JS, что делает Page Intelligence переносимой по определению.
- Нет Google-сервисов и телеметрии Chrome в составе CEF по умолчанию.

Минусы и что с ними делать:
- UI браузера (вкладки, омнибокс, настройки, менеджер паролей, загрузки) пишем сами → Shell на
  TypeScript в привилегированном WebUI-контексте CEF (ADR-002), поэтапно.
- Бинарь ~150–250 МБ — приемлемо для десктопа.
- Расширения Chrome в CEF работают без Web Store UI и с ограничениями — заявляем как best-effort
  (ADR-008).
- Зрелость Rust-биндингов CEF — риск; митигируется резервным бэкендом `webview2` и тем, что ядро
  не знает о движке.
- На WKWebView нет доступа к сети на уровне CDP → DevTools-функции (D-1) на iOS ограничены;
  честно помечаем как desktop-only.

## Метрики пересмотра

Пересмотреть ADR, если: (а) Servo достигнет реальной web-compat и стабильного LTS API — как
движок для лёгкого «reader/agent view»; (б) потребуется > 3 патчей в Chromium — сравнить CEF с
patch-set против минимального форка; (в) Rust-биндинги CEF не закроют нужный API за первый
инкремент — перейти на `webview2`.
