# ADR-007 — Маршрутизация моделей по чувствительности и модель приватности

Статус: принято (2026-09).

## Контекст

Гибридный режим: локальные модели по умолчанию, облако — по желанию пользователя (BYOK).
Требования: приватные данные не покидают устройство; пользователь всегда видит, куда ушёл
запрос; полный офлайн-режим; нулевая телеметрия. Comet отправляет контекст страниц на сервер и
хранит 30 дней — это ровно то, чего мы не делаем.

## Варианты

1. Классификация чувствительности **моделью** — гибко, но недетерминированно и само требует
   отправки данных модели.
2. **Детерминированные классы по источнику данных** — грубее, но проверяемо и объяснимо.
3. Без маршрутизации: пользователь выбирает провайдера вручную — перекладывает ответственность.

## Решение

- Класс чувствительности вычисляется **детерминированно по источнику** (crate `policy`):

| Класс | Источник | Разрешённые провайдеры |
|---|---|---|
| `secret` | маскированные поля, cookies, `Authorization`/`Set-Cookie`, ключи API в DevTools | никакие (редактируется до Model Gateway) |
| `private` | страницы за логином (обнаружение: наличие cookie сессии/`Cache-Control: private`/страница в профиле пользователя), почта/мессенджеры/банки (списки), история, память, DevTools-трафик, локальные файлы | только `local` |
| `personal` | реплики пользователя, в которых детектор PII нашёл ФИО/адрес/телефон/номер карты | `local`; `cloud` — только с явным переключателем на этот запрос |
| `public` | публичные страницы без сессии, общие вопросы, реплики без PII | `local` по умолчанию; `cloud`, если пользователь включил «облачное планирование/ответы» |

- Класс запроса = максимум классов частей. Провайдер выбирается из **отсортированного списка
  предпочтений** внутри разрешённого множества (`smart → fast → cpu`), с учётом доступности VRAM.
- В каждом ответе UI показывает бейдж: провайдер, модель, класс, число токенов; для облака —
  сколько байт и каких артефактов ушло (перечень `obs_id`/`mem_id`).
- **Офлайн-режим**: один переключатель отключает все не-`local` провайдеры и любые исходящие
  соединения ИИ-слоя (реализуется в Model Gateway и дублируется сетевой политикой процесса).
- **Что никогда не покидает устройство**: сырое содержимое страниц за логином, история, память,
  эмбеддинги, журнал агента, DevTools-данные, локальные файлы. Даже при включённом облаке в него
  уходят только реплики пользователя и `public`-наблюдения, и только те, что нужны текущему шагу.
- **Прозрачность памяти**: инспектор (`browser://memory`) показывает записи с источником и датой,
  поиск, удаление с каскадом, экспорт в JSON, «забыть домен», «забыть период». Приватные окна не
  индексируются. Список доменов «никогда не запоминать» (банки, медицина — предзаполнен).
- **Телеметрия**: отсутствует. Нет crash-репортинга по сети; локальный crash-лог с кнопкой
  «скопировать». Проверки обновлений — только явные или по опции, без идентификаторов.
- Ключи облачных провайдеров — в OS keychain (Windows Credential Manager / iOS Keychain).

## Последствия
- Часть публичных страниц будет ошибочно признана `private` (ложноположительные) — это безопасная
  сторона ошибки; пользователь может понизить класс для домена.
- Облачное планирование агента работает только над `public`-наблюдениями → на приватных сайтах
  агент планирует локальной 8B-моделью, что снижает успех сложных задач. Принимаем как цену
  приватности и компенсируем WebMCP/записанными сценариями.
