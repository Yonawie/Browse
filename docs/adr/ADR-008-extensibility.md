# ADR-008 — Расширяемость: плагины-инструменты агента, MCP, WebExtensions

Статус: принято (2026-09).

## Контекст

Аудитория — разработчики; они захотят добавлять инструменты агенту (Jira, GitHub CLI, локальные
файлы), подключать внешних агентов (Cursor, Claude Code) к браузеру и ставить привычные
расширения. Урок Comet: скрытый MCP-API `addStdioServer`, исполняющий локальные команды без
согласия, — недопустим. WebMCP (Chrome 149 origin trial) даёт стандарт для инструментов **со
стороны сайта**; MCP — для инструментов **со стороны пользователя**.

## Решение

### Инструменты агента (Tool Plugins)
- Инструмент = манифест (`schemas/tool-manifest.schema.json`) + реализация. Манифест объявляет:
  имя, описание для модели, JSON-схему аргументов с пометками `free_text_ok`/`ref_only`,
  `consequential`, `read_only`, требуемые capabilities (`net:<host>`, `fs:read:<path>`,
  `clipboard`, `browser:tab:<scope>`), класс чувствительности выхода.
- Рантаймы плагинов: **WASM (wasmtime, WASI preview 2)** — по умолчанию, без capability нет
  доступа; **внешний процесс по MCP (stdio)** — только по явной установке пользователем с показом
  манифеста и прав, всегда виден в настройках, включается per-task.
- Встроенные инструменты ядра (`navigate/click/type/select/scroll/extract/read_more/
  search_memory/…`) описаны теми же манифестами — политики едины.

### Внешние агенты → наш браузер
- Локальный **MCP-сервер браузера** (`browser-mcp`) экспортирует тот же набор инструментов, что и
  внутренний агент, **с теми же политиками** (изолированный профиль, scope, подтверждения,
  журнал). Включается только в явном dev-режиме, слушает localhost с одноразовым токеном,
  каждый клиент виден в UI. Это замена «Claude in Chrome/Playwright MCP», но безопасная по умолчанию.

### Инструменты сайта → наш агент
- Поддержка **WebMCP** (Declarative + Imperative) в сенсоре: инструменты сайта попадают в
  `Observation.tools[]`, хинты `consequentialHint`/`readOnlyHint`/`untrustedContentHint`
  маппятся на наши правила (ADR-005 §6). WebMCP предпочтительнее DOM-действий.

### WebExtensions
- Через CEF Chrome runtime — установка из файла/URL CRX, без Web Store UI; поддерживаемый набор
  API — тот, что даёт Chromium в CEF; заявлено как **best-effort**. Расширения **не имеют доступа**
  к агентному профилю по умолчанию. На iOS — нет.

### Skills / сценарии
- Записанные сценарии (A-6) и пользовательские «навыки» (промпт + набор инструментов + scope) —
  JSON-файлы в профиле, экспортируемые; не исполняют код, только конфигурируют рантайм.

## Последствия
- Единая точка enforce'а политик для внутренних и внешних агентов и плагинов.
- Ограниченная совместимость расширений — честно документируем; ставка на инструменты агента.
