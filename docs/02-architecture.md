# 02 — Архитектура

Документ описывает целевую архитектуру браузера с ИИ в ядре. Решения, на которые он опирается,
зафиксированы в `docs/adr/`. Код-скелет слоёв — в `crates/`, схема данных — в `schema/memory.sql`,
JSON-схемы манифестов и политик — в `schemas/`, сенсор страницы — в `sensor/`.

Рабочее имя проекта: **Browse** (по имени репозитория).

## 0. Принципы

1. **ИИ — часть модели данных браузера**, а не боковая панель: история, вкладки, DOM и сеть
   — это входы Page Intelligence и Memory; ответы и действия — выходы Agent Runtime.
2. **Безопасность — архитектурная, не модельная** (ADR-005): рантайм enforce'ит правила
   детерминированно; модель — недоверенный компонент, как и страница.
3. **Локально по умолчанию, облако — по явному согласию, никогда — телеметрия** (ADR-007).
4. **Обычный сёрфинг не должен деградировать**: ИИ-слой живёт в отдельных процессах/потоках,
   работает в простое, уступает GPU композитору, имеет бюджеты (§5).
5. **Один код ядра для двух движков** (ADR-001/002): всё, что зависит от движка, — за
   `EngineAdapter`; всё, что зависит от платформы, — за Shell.

Процессная модель (десктоп): стандартная многопроцессность Chromium (browser / renderer /
GPU / network / utility) + наш Rust-код в browser-процессе (Core) + `llama-server` как отдельный
процесс + WASM-плагины в утилитарных потоках с ограничениями. Сенсор страницы исполняется в
renderer-процессе в **изолированном мире** и не имеет доступа к JS страницы (и наоборот).

### 1.1. Shell
- Вкладки, окна, группы вкладок (в т.ч. автогруппировка), сайдбар ассистента, омнибокс на
  естественном языке с индикатором интерпретации, модальные подтверждения агента с превью, поток
  действий агента с кнопкой «стоп», инспектор памяти (`browser://memory`), настройки моделей
  и политик (`browser://ai`), дев-режим (`browser://dev`).
- Shell не содержит логики ИИ; всё — вызовы Core по IPC.
- Агентный профиль визуально отличается (цвет рамки, бейдж) — «уменьшение удивления» как у Brave.

### 1.2. Engine Adapter (`crates/engine-adapter`)
Трейт `EngineAdapter` (см. код) абстрагирует: создание/закрытие webview в указанном профиле,
навигацию, инжекцию сенсора в изолированный мир, вызов функций сенсора, подписку на события
(навигация, загрузка, мутации из сенсора, сеть — где доступна), ввод (клик/тайпинг по `ref`),
скриншот, управление профилями (изолированный агентный профиль, импорт cookies одного origin).

| Возможность | `cef` (CDP) | `wkwebview` | `cdp-remote` |
|---|---|---|---|
| Изолированный мир для сенсора | `Page.addScriptToEvaluateOnNewDocument{worldName}` | `WKContentWorld` + `WKUserScript` | как cef |
| AX-дерево | `Accessibility.getFullAXTree` | нет (эвристики сенсора) | как cef |
| Сеть (наблюдение, редактирование секретов) | `Network.*`, `Fetch.*` | только `WKURLSchemeHandler`/rule lists — частично | как cef |
| Ввод | `Input.dispatch*` (доверенные события) | JS-события из сенсора (недоверенные) + `WKWebView` API | как cef |
| Отдельный профиль | отдельный `CefRequestContext` | `WKWebsiteDataStore(forIdentifier:)` | отдельный `--user-data-dir` |
| Импорт cookies origin | `Network.setCookies` | `WKHTTPCookieStore` | как cef |

### 1.3. Page Intelligence (`crates/page-intelligence`, `sensor/`)
- **Сенсор** (TS, изолированный мир): строит `Observation` (ADR-006) по требованию и по
  дебаунсированным мутациям в простое (`requestIdleCallback`, ≤ 1 снимок / 2 с при активности,
  0 в фоне вкладки); извлекает основной текст (readability-подобно); собирает WebMCP-инструменты;
  помечает `suspect_injection`; никогда не читает маскированные поля и cross-origin iframe без гранта.
- **Ядро**: чанкинг (по заголовкам, 200–400 токенов, перекрытие 10%), определение `page_kind`,
  структурное извлечение по схеме (через Model Gateway с грамматикой), суммаризация, диффы версий,
  очередь эмбеддингов (батчи по 32, только в простое, только для вкладок в профиле пользователя и
  вне «никогда не запоминать»).
- Стоимость в простое: сенсор ~0 (нет мутаций — нет работы), очередь эмбеддингов — ограничена
  `idle`-детектором ОС и бюджетом 5% CPU (токен-бакет).

### 1.4. Memory (`crates/memory`, `schema/memory.sql`)
- SQLite + sqlite-vec + FTS5 (ADR-004). Репозиторий с операциями: записать визит/страницу/версию,
  чанки и векторы, гибридный поиск (RRF), граф (сущности/рёбра), задачи, память пользователя
  (только с провенансом `user`/`confirmed`), каскадное удаление, экспорт.
- Поиск: `search(query, filters{time, domain, task, kind}, k)` → FTS5 top-50 ⊕ vec top-50 → RRF →
  дедупликация по странице → top-k с цитатами (`chunk_id`, `char_range`).

### 1.5. Agent Runtime (`crates/agent-runtime`)
Цикл задачи:

```
user_request ─► classify_intent ─► (если agent) plan(scope) ─► show scope ─► loop:
   observe(tab) ─► propose(tool_call) ─► policy.check(call)  ─► critic.review(call)
   ─► [confirm?] ─► execute ─► journal ─► until done | max_steps | stop
```

- `TaskScope`: origins, tools, max_steps, max_duration, money_limit=0, profile=isolated.
- `ToolRegistry`: встроенные инструменты + плагины (ADR-008) с манифестами.
- `PolicyEngine.check` (детерминированно): scope, allow-list, cross-origin data-flow по
  провенансу аргументов, `secret`-блок, consequential-классификация → `Allow | Confirm(reason) | Deny(reason)`.
- `Critic`: «слепой» ревьюер (ADR-005 §5) — трейт, реализация через Model Gateway на `fast`.
- `ExecutionMode`: `Live | DryRun` (dry-run останавливается перед первым consequential).
- `Journal`: append-only `agent_actions` + хэши наблюдений до/после.
- Восстановление: при исчезновении `ref` — повторный снимок и поиск по семантическому пути;
  CAPTCHA/анти-бот — стоп и передача управления человеку.

### 1.6. Model Gateway (`crates/model-gateway`)
- Трейт `ModelProvider` (chat со стримингом и инструментами, structured output по JSON-schema,
  embeddings), реализации: `LlamaServer`, `Ollama`, `OpenAiCompatible`, `Anthropic`, `Gemini`,
  `AppleFoundationModels` (через UniFFI callback).
- `Router`: вход — запрос с классом чувствительности и требуемой ролью (`fast|smart|vision|embed`),
  выход — конкретный провайдер/модель из разрешённого множества (ADR-007) с учётом состояния VRAM.
- `ModelManager`: жизненный цикл `llama-server`, загрузка/выгрузка моделей (LRU, таймаут простоя),
  бюджет VRAM, health-check, рестарт; каталог моделей и пресеты под железо.
- Кэш: по хэшу (модель, промпт, грамматика) для суммаризаций/извлечений; лимиты: токены/мин,
  параллелизм, тайм-ауты; учёт стоимости облака в `model_calls`.

### 1.7. Policy & Security (`crates/policy`)
- Классы чувствительности по источнику; провенанс значений; гранты (`grants`: тип, субъект,
  объект, TTL, задача); правила data-flow; классификатор consequential; списки запретов;
  аудит (все решения политики пишутся в журнал).

## 2. Модель безопасности агента (сводка ADR-005)

| Механизм | Где enforce | Обходится моделью? |
|---|---|---|
| Изолированный профиль; импорт сессии одного origin на одну задачу | Engine Adapter + grants | Нет |
| Страница = данные с провенансом; cross-origin iframe по гранту | Sensor + core-types | Нет |
| Cross-origin data-flow policy (SOP для агента) | PolicyEngine по меткам аргументов | Нет (метки ставит рантайм) |
| Scope задачи, allow-list инструментов, лимиты | PolicyEngine | Нет |
| Слепой критик | Agent Runtime → Model Gateway (`fast`, без страниц) | Частично (вероятностный) |
| Consequential → подтверждение с превью; dry-run | PolicyEngine + Shell | Нет |
| Журнал, живой поток, стоп | Agent Runtime + Shell | Нет |
| Запреты URL/полей; классификатор инъекций как сигнал | Sensor + PolicyEngine | Нет / вероятностный |

Красная команда в CI: `tests/redteam/` — страницы с инъекциями (мультиязычные, разнесённые по
секциям, в iframe, в alt/aria/title, в WebMCP-описаниях инструментов); проверяем, что
детерминированные правила блокируют cross-origin перенос и consequential-действия **независимо
от вердикта модели**.

## 3. Модель приватности (сводка ADR-007)

- Никогда не покидает устройство: содержимое страниц за логином, история, память, эмбеддинги,
  журнал агента, DevTools-данные, локальные файлы, секреты.
- Облако (BYOK, выключено): только реплики пользователя и `public`-наблюдения текущего шага.
- Пользователь видит: бейдж провайдера/класса на каждом ответе; инспектор памяти с источником
  каждой записи; «что ушло в облако» по каждому запросу.
- Удаление: по записи, по домену, по периоду, всё; каскад до векторов и рёбер графа;
  `VACUUM` по расписанию для реального стирания.
- Офлайн-режим: выключает не-`local` провайдеров и исходящие соединения ИИ-слоя.
- Телеметрии нет. Обновления — без идентификаторов.

## 4. Производительность и бюджеты

Референсная машина: Windows 11, 8 ГБ RAM, RTX 4060 8 ГБ, NVMe. Бюджеты — гейты в CI/бенчах.

| Метрика | Бюджет | Как достигаем |
|---|---|---|
| Холодный старт до интерактивного UI | < 2.0 с | CEF init параллельно с Shell; ИИ-слой ленивый: sidecar стартует после первого кадра, модели грузятся по первому запросу или в простое |
| Первый ответ «быстрой» модели после старта | < 4 с (включая загрузку 2.5 ГБ) | предзагрузка `fast` в простое через 10 с после старта, если пользователь включил |
| Суммаризация страницы (≤ 3K токенов) | p95 < 3.0 с | `fast` (Qwen3-4B) резидентна; prefill ~1.2 с + 150 токенов @ 80 tok/s |
| Снимок страницы сенсором (обычная страница) | p95 < 50 мс на главном потоке страницы, в чанках по 8 мс | инкрементально, `requestIdleCallback`, кэш по узлам |
| Накладные расходы Page Intelligence в простое | < 5% CPU одного ядра, 0 в фоне | нет мутаций — нет работы; очередь эмбеддингов по токен-бакету |
| Резидентная RAM ИИ-слоя (CPU) | < 300 МБ в простое, < 600 МБ при работе | тяжёлое — на GPU в sidecar; ONNX-модели маленькие |
| VRAM | `fast`+`embed`+1.5 ГБ запас композитору ≤ 8 ГБ; `smart` вытесняет `fast` | ModelManager с бюджетом |
| Поиск по памяти (200K чанков) | p95 < 50 мс | партиции по месяцам, 256-dim, FTS5 предфильтр |
| Шаг агента (наблюдение → действие) локально | p95 < 6 с на `smart` | снимок ≤ 4K токенов, `diff`-снимки, кэш префикса KV в llama-server |
| Рост БД | ≤ 1 ГБ / 50K страниц | zstd для текста, TTL, лимит |
| Влияние на скорость загрузки страниц | < 2% по Speedometer/PLT с включённым сенсором | сенсор запускается после `load`/idle, без синхронных обходов |

Как ИИ-слой не деградирует сёрфинг: (1) отдельный процесс инференса с приоритетом ниже
нормального и лимитом VRAM; (2) сенсор — только в простое страницы, дебаунс, лимит времени на
кадр; (3) эмбеддинги — только когда ОС в простое и питание не от батареи (настраивается);
(4) любые ИИ-функции можно выключить одним переключателем — браузер остаётся браузером.

## 5. Расширяемость (сводка ADR-008)

- Инструменты агента — WASM (wasmtime, WASI p2) или внешний MCP-процесс по манифесту с
  capabilities; единый `ToolRegistry` и политики.
- `browser-mcp` — локальный MCP-сервер для внешних агентов (Cursor/Claude Code) с теми же
  политиками; только dev-режим, localhost, токен.
- WebMCP сайтов — предпочтительная актуация.
- WebExtensions — через CEF Chrome runtime, best-effort, без доступа к агентному профилю.
- Skills/сценарии — декларативные JSON-файлы.

## 6. Схема данных

Полная DDL — `schema/memory.sql` (SQLite). Ниже — сущности и связи.

```
profiles 1──* visits *──1 pages 1──* page_versions 1──* chunks 1──1 chunk_vectors (vec0)
                                    │                     │
                                    │                     └──* entity_mentions *──1 entities *──* edges
                                    └──* tabs (текущее состояние вкладок) *──1 tab_groups *──1 tasks

tasks 1──* agent_sessions 1──* agent_steps 1──* agent_actions ──* approvals
agent_sessions ──* grants (импорт сессии origin, cross-origin разрешения, TTL)
memories (факты о пользователе; provenance ∈ {user, confirmed}; supersedes)
scenarios 1──* scenario_steps (записанные сценарии по семантическим путям)
model_calls (локальный аудит вызовов моделей: провайдер, класс, токены, стоимость, латентность)
policy_decisions (аудит решений PolicyEngine)
settings, schema_migrations
```

Ключевые инварианты схемы:
- `chunks.sensitivity` наследуется от `page_versions.sensitivity`; `secret` не сохраняется никогда.
- `memories.provenance IN ('user','confirmed')` — CHECK-ограничение; наблюдения со страниц — в
  `chunks`, не в `memories`.
- `agent_actions` append-only (триггер запрещает UPDATE/DELETE); `grants` имеют `expires_at`.
- Каскады: `pages → page_versions → chunks → (trigger) chunk_vectors, entity_mentions`.
- Все времена — `INTEGER` unix ms UTC.
